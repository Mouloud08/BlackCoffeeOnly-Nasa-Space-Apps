# FireBridge demo video and fallback slides

- `out/firebridge-demo.mp4`: the 28.5-second demo (1920×1080, H.264 yuv420p, 30 fps, faststart, English voice-over as one
  AAC track; the captions carry the same words, so it also works muted).
- `out/firebridge-slides.pdf`: the 7-slide fallback (16:9). Previews: `out/slides/*.png`.

Everything on screen comes from real captures of `dist/firebridge.html` (light theme, real clicks, visible cursor).

## Re-render (one command)

```sh
node video/render.mjs C:/path/to/firebridge.html
```

This captures the five shots again (`capture.mjs`), checks every caption number against the text of the captured screen
(it stops if one is missing), renders with Remotion, re-encodes for the web, verifies the result with ffprobe
(≤ 28.6 s, 1920×1080, H.264 yuv420p, 30 fps, < 15 MB, faststart, one AAC track when `public/voice.mp3` is there), saves one frame per shot in `out/frames/`, rebuilds the slides
(`slides.mjs`) and prints the final duration. About 4–5 minutes. Look at `out/frames/*.png` before publishing.

Options: `--skip-capture` (captions edited only), `--skip-slides`, `--force` (render despite a number mismatch; not for the final).
First run: `npm install` inside `video/` (render.mjs does it if `node_modules` is missing).

## Where things live

- `captions.json`: ALL on-screen text and timing (shots, captions with start/end in seconds, end card). `*x*` = emphasis.
- `capture.mjs`: the hash opened and the scripted clicks for each shot (selectors by id/class/role, not by label).
- `src/Demo.jsx`: the Remotion composition (window, caption band, cross-fades, end card, voice track); `slides.mjs`: the deck.
  Both draw the app's mark (concept A, `docs/logo/concept-a.svg`) inline, in the ink colour.
- `voice.mjs`, `voice.json`, `public/voice.mp3`: the voice-over (see below).
- `public/fonts/`: the app's fonts (Atelier Texte, Radio Canada). `public/captures/`: generated clips (not in git).

## Voice-over

`public/voice.mp3` (28.4 s, mono, 192 kb/s, about −17 LUFS, true peak about −1 dBTP) is in the repository: every render, including a full
re-capture run, lays it under the whole video automatically (`Demo.jsx` picks up `public/voice.(mp3|wav|m4a|aac)`) and the output gets
one AAC track; `render.mjs` stops if the file is there but the MP4 has no audio. The track is timed to `captions.json` (the timeline), not to
the captured footage, so a re-capture does not need a new voice. Regenerate it only if a caption's text or start time changes.

It is generated by `voice.mjs` with ElevenLabs: voice **Chris** (premade, American English, male, middle-aged, "down-to-earth"),
model `eleven_multilingual_v2`, stability 0.6, similarity 0.75, style 0, speed 1.12. One clip per caption (plus a short end-card line),
each trimmed of its edge silence, inner pauses capped at 0.2 s, placed at its caption's start; a clip must end 0.15 s before the next starts
and the last before 28.3 s, or the script stops. TTS takes vary in length, so the script keeps the first of `--tries` takes that fits.
The narration reads the captions ("×" as "times", "±10%" as "within ten percent"; the sensor names are written as said, "Modis"
and "veers", so the model never spells them out); the words are in `SEGMENTS` in `voice.mjs`, and
`voice.json` records the voice, model, text, start and duration of each clip (no key, no header).

```sh
# list the account's voices and models (names, categories, labels only)
node video/voice.mjs --env-file=<path/to/.env holding ELEVENLABS_API_KEY> --list
# generate all clips, check the timing, mix public/voice.mp3
node video/voice.mjs --env-file=<path> --voice=iP95p4xoKVk53GoZ742B --model=eleven_multilingual_v2 --speed=1.12 --tries=6
# only some clips again (e.g. after editing one line); --text1="…" tries another wording without editing the file
node video/voice.mjs --env-file=<path> --voice=iP95p4xoKVk53GoZ742B --speed=1.12 --tries=6 --only=1,7
# re-mix public/voice.mp3 from the saved clips (no network, no key), then render
node video/voice.mjs --assemble
node video/render.mjs --skip-capture
```

The key is read at run time from the env file named by `--env-file=` (or the `FB_VOICE_ENV_FILE` environment variable); only the
`ELEVENLABS_API_KEY` line is read, the key is never printed, logged or written, and the only host contacted is `api.elevenlabs.io`.
The per-clip files (`voice/clips/`, ~2 MB) are not in git; `public/voice.mp3` is. Without a key, `--assemble` and the render still work.
